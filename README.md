MyWayApps is a Next.js kids' learning app covering English, Hindi, Kannada, Tamil, Malayalam, Telugu, and Sanskrit — vocabulary, letters, poems, and reading-comprehension lessons, each with natural-sounding audio via Azure Neural TTS.

## Getting Started

```bash
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

## How audio works

Every "speak" button in the app tries, in order:

1. **Browser voice** — if the device has a decent native voice for that language (`hooks/use-tts.ts`, `lib/static-tts.ts`), it's used directly, free and instant.
2. **Pre-generated static file** — `public/audio/<lang>/<hash>.mp3`, a SHA-256 hash of the exact text. This is the normal path for real content and is committed to git, so it costs nothing at runtime.
3. **Live Azure call** — `/api/tts` (`app/api/tts/route.ts`), only hit when a browser voice is unavailable *and* no static file exists yet for that text. Falls back further to eSpeak if Azure isn't configured or a request fails — this is what makes local dev work even without an Azure key, just with a more robotic voice.

Sanskrit has no TTS voice anywhere (Azure, Google Cloud, or otherwise) — its audio is generated by transliterating the text to Kannada script and speaking it with the Kannada voice (`lib/sanskrit-tts.ts`). This happens automatically; you never write Kannada text yourself.

## Adding new content

Add content in the relevant `lib/*.ts` data file — no route or page changes needed for any of these, the existing pages read from these files automatically. After adding content, **run the audio generator (see below) and commit the new files under `public/audio/`** so the new words/lessons have sound before anyone hits them live.

| Content type | File(s) | Shape |
|---|---|---|
| Vocabulary | `lib/<lang>-vocabulary-data.ts` | Add an item to a category's `items: [{ english, <lang> }]`, or a whole new category to `vocabularyCategories` |
| Letters | `lib/<lang>-letters-data.ts` | Add `{ letter, word }` to `<lang>Vowels`/`<lang>Consonants`. For every language except Telugu, `word` is native script + English gloss in parentheses, e.g. `"अनार (Pomegranate)"` — the gloss is stripped automatically before audio generation, don't worry about it |
| Poems | `lib/poems-data.ts` | Add a `{ id, title, titleEnglish, lines: [...] }` object to `POEMS[lang]`. The whole poem is spoken as one line (all `lines` joined with a space) |
| Comprehension lessons | `lib/<lang>-comprehension-data.ts` | Add a new object to `comprehensionLessons` with a **unique `id`** (next integer), `passage: [...]` (spoken line by line), `game1Questions: [{ question, options, correctAnswer }]`, `game2Questions: [{ sentence, blank, options, correctAnswer }]` (`sentence` must contain the literal `blank` text once, e.g. `sentence: "बिल्ली _____ रंग की है।", blank: "_____"`) |
| Telugu riddles | `lib/telugu-riddles-data.ts` | Add `{ id, podupu, vidupu, englishAnswer, reason }` — Telugu-only, no equivalent file for other languages yet |

To add a genuinely **new language or content type** (not listed above), you'll also need new page routes and a `scripts/generate-audio.js` config entry — that's a real code change, not just a data edit.

## Generating audio

```bash
# one-time setup: create an Azure AI Speech resource (portal.azure.com → "Speech service"),
# then add its key + region to .env.local:
AZURE_SPEECH_KEY=your-key
AZURE_SPEECH_REGION=your-region   # e.g. centralindia

npm run generate-audio
```

This scans every `lib/*.ts` data file listed above, finds every unique piece of native-script text actually spoken in the app, and generates an MP3 for anything not already cached under `public/audio/<lang>/` — **existing files are never regenerated**, so re-running after adding a few new words is fast and only pays for what's new. It also writes `public/audio/<lang>/manifest.json` (hash → source text, useful for debugging what a given file is).

It runs automatically before `npm run build` (`npm run prebuild`), so a real deploy build always has up-to-date audio — but for local dev, run it manually after adding content so you can hear it right away.

**Voice per language** (one fixed voice each, for a consistent "character"): edit `AZURE_VOICE_MAP` in **both** `lib/azure-tts-voices.ts` (used by the live `/api/tts` route) and `scripts/generate-audio.js` (used by this generator — duplicated because the generator runs as plain Node, not through Next.js) — keep the two in sync.

| Lang | Current voice | Alternative (other gender) |
|---|---|---|
| English | en-IN-NeerjaNeural (F) | en-IN-PrabhatNeural (M) |
| Hindi | hi-IN-MadhurNeural (M) | hi-IN-SwaraNeural (F) |
| Kannada | kn-IN-GaganNeural (M) | kn-IN-SapnaNeural (F) |
| Tamil | ta-IN-PallaviNeural (F) | ta-IN-ValluvarNeural (M) |
| Malayalam | ml-IN-SobhanaNeural (F) | ml-IN-MidhunNeural (M) |
| Telugu | te-IN-ShrutiNeural (F) | te-IN-MohanNeural (M) |

Sanskrit has no entry of its own — it always follows Kannada's voice (see "How audio works" above), so changing Kannada's voice changes Sanskrit's too.

**Cost**: the entire app's content is currently ~27,000 characters, all one-time (generated once, cached in git forever after). Azure's free tier is 500,000 characters/month and never expires — you'd need to add roughly 15–20x the app's current total content in a single month to get anywhere near that limit.

**No Azure key configured?** The generator (and the live `/api/tts` route) fall back to eSpeak automatically — audio still gets generated, just more robotic-sounding. Fine for a quick local check, not recommended for anything you're going to commit.
